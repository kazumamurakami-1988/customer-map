# Inbox Triage — 未返信メールの仕分け＆返信ドラフト

受信箱の「自分が返す番」のメールを拾い、緊急度で仕分けして、要返信のものは**返信ドラフトをGmailの下書きに用意**する。最後に一覧を本人のSlack DMに送る。本人は朝、下書きを確認して送るだけ。

スケジュール実行（推奨: 平日 7:30。必要なら +14:00 の2回目も）または「受信箱トリアージ」と言われたときに走らせる。

## 手順

ツールは ToolSearch で都度ロード（MCPサーバIDはセッションで変わりうるので名前で探す）。

### 1. 未返信メールを集める

`search_threads` で受信箱を確認:
- `in:inbox newer_than:5d`（直近の受信）を起点に、各スレッドの**最後の送信者が自分でない**もの＝自分のボール＝要返信候補。
- 除外（ノイズ）: GitHub/Instagram/Etsy/Notion等の通知、freeeなどの自動送信(noreply)、メルマガ・プロモーション(`category:promotions/social`)、配信失敗通知(MAILER-DAEMON等)。ただし配信失敗は「再送が要る実務」として別枠で拾う。
- 迷うものは `get_thread` で本文を読んでから判断する。スレッドの文脈（何を聞かれているか、期日があるか）を把握する。

### 2. 緊急度で仕分け

各メールを次の3段階に分類:
- **🔴 今日中**: 期日が今日/明日、相手が返事待ちで止まっている、商談・請求・契約など金や約束に関わる。
- **🟡 今週中**: 返した方がいいが急ぎではない。確認・調整系。
- **⚪ 低/様子見**: 情報共有でリアクション程度でよい、または自分の対応不要。

各メール: 差出人・件名・要点1行・「何を返すべきか」1行・緊急度。

### 3. 要返信のものに返信ドラフトを作る

🔴・🟡 で「明確に返信が要る」ものは、`create_draft` で**スレッド内の返信下書き**を作る:
- `replyToMessageId` = そのスレッドの最新メッセージID、`to` = 返信先、`subject` = 元件名（Re:）。
- 本文は本人の声で、過不足なく。確定できない部分（日程の候補、金額、添付など）は `（※ここに〇〇を記入）` のプレースホルダを置き、勝手に事実を作らない。
- 1通ずつ作る。下書きは1スレッド1通まで（既に下書きがあればスキップ）。
- ⚪ や、内容が曖昧で下書きが書けないものは、ドラフトを作らず一覧に「要手動」と記す。

### 4. 一覧を自分宛DMに送る

`slack_send_message` で channel_id = `U09FJ733J0Y`。構成例:

```
📥 受信箱トリアージ（6/9 7:30時点 / 未返信 4件）

🔴 今日中（2件）
・黒川さん｜経産省施策の確認時間 → 候補日を返す。✍️下書き用意済み（日程は要記入）
・〇〇さん｜請求書の支払期日 → 入金予定を返信。✍️下書き用意済み

🟡 今週中（1件）
・△△さん｜資料へのフィードバック → お礼＋反映予定を返信。✍️下書き用意済み

⚪ 低（1件）
・□□社｜ニュースレター的な共有 → 対応不要。

⚠️ 別件: 6/7「5稿」添付がサイズ超過で不達。再送が必要（要手動）。

→ 下書きはGmailの「下書き」フォルダに入れてあります。確認して送信を。
```

- 下書きを作った件は `✍️下書き用意済み`、作れなかった件は `要手動` を明記。
- 0件のセクションは「なし」と1行。件数はヘッダに出す。
- 最後に「下書きフォルダを見て」と一言。

## 手動実行のとき

「受信箱トリアージ」「メールの返信下書き作って」等で上の手順を実行。
「送らずに見せて」と言われたら、下書きは作ってよいがSlack送信はせずチャットに一覧を出す。
特定の相手/件名を指定されたら、その範囲だけ処理する。
